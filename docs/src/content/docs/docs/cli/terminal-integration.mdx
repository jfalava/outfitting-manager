Outfitting reports what it is doing through the [Program Status Protocol, OSC 7501](https://www.superlogical.com/rex/docs/build/program-status). Compatible terminals, including Rex, can show progress, requests for input, completion, and failures. No terminal-specific setup is required.

The terminal decides whether updates appear as indicators, notifications, or sounds. Terminals that do not support the protocol ignore the reports.

## Phases and progress

Window titles follow the current phase, such as `Outfitting: Building`, `Outfitting: Installing curl 33%`, or `Outfitting: Password required`. Package-operation percentages count completed attempts, including failed attempts. Work without a known total has no percentage.

Interactive setup questions, plan approvals, credential configuration, and Nix sudo authentication report that they are waiting for input. Answers and credential values are never included in status reports.

Completion leaves `Outfitting: Done`; failures leave `Outfitting: Failed`. Cancellation reports an idle state with `Outfitting: Cancelled`. Completed and failed records remain available to the terminal after the command exits. Titles are not restored by Outfitting; your shell may replace them at its next prompt.

## Disable status reporting

To disable both status reports and window-title updates:

```bash
export OUTFITTING_PROGRAM_STATUS=0
```

Reports go to stderr only when it is a terminal and `TERM` is not `dumb`. Redirected stderr stays free of terminal controls, and stdout remains available for command output. Help, version, and argument-validation output do not start reporting. Outfitting never reads stdin to detect support.

When reporting is disabled, password and fatal-error alerts retain the terminal bell. Successful commands do not emit a bell.
