`nix` is available on macOS and Linux. It operates on the selected `config.toml` profile. A bare `nix` command lists actions without running one. Successful `build`, `test`, `dry-run`, and `switch` actions publish related Nix lock state unless `--no-push` is set. `nix update` always publishes its lock after a successful activation.

## `build`

Builds the configured system without activating it. On Linux, builds the Home Manager activation package; on macOS, builds the nix-darwin system.

## `switch`

Builds and activates the selected Home Manager profile on Linux or nix-darwin system on macOS.

## `test`

Test-builds the configured system without activating it.

## `dry-run`

Runs the Nix dry-run build without activating the configured system.

## `update`

Updates every input in the selected flake, builds the updated Home Manager profile on Linux or nix-darwin system on macOS, activates it, then publishes the new lockfile to the lockfiles service. It starts from the latest remote Nix lock when one exists; the source's local `flake.lock` is used to bootstrap a machine without a remote lock. A failed build or activation does not publish the candidate lock.

```sh
outfitting-manager nix update [--profile <profile>] [--no-refresh] [--if-configured]
```

## Options

| Option | Availability | Description |
| --- | --- | --- |
| `--profile <profile>` | macOS, Linux | Override the platform profile selected in `config.toml`. |
| `--no-refresh` | macOS, Linux | Use the local source without fetching remote changes. |
| `--no-push` | macOS, Linux | Keep successful Nix lock changes local. |
| `--if-configured` | Linux | Skip when the selected profile declares no Nix flake. |
