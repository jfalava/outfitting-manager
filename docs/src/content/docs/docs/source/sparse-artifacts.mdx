Use a remote source when your declarations are stored in Git. Set its repository and branch, tag, or other Git ref in `config.toml`:

```toml
[source]
repository = "https://github.com/your-account/dotfiles"
ref = "main"
```

Outfitting retrieves the files needed for the selected platform and profile, rather than copying the whole repository. To use a local checkout instead, see [Local sources](/docs/source/local-sources/).

## Refresh the source

Source refresh depends on the command:

- `init`, Linux/macOS `apply`, and Linux/macOS `nix` refresh by default. Use `--no-refresh` where available to reuse the saved copy.
- Linux `diff` uses the saved copy by default. Pass `--refresh` to fetch it again.
- Windows `apply`, macOS/Windows `diff`, `validate`, `status`, and `source path` do not refresh the remote source.

```sh
# Refresh the remote source
outfitting-manager init

# Reuse the existing copy
outfitting-manager init --no-refresh
```

`--no-refresh` controls the source copy only; it does not prevent package managers or Nix from using the network.

## Access and requirements

For a private GitHub repository, sign in with the GitHub CLI and use an account that can read the repository. For GitHub Enterprise, use its hostname:

```sh
gh auth login --hostname github.com
gh auth login --hostname github.example.com
```

Other Git hosts use your configured Git credentials. Remote sources do not support symlinks or submodules; use a [local checkout](/docs/source/local-sources/) if your source needs them.
