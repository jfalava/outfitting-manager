Store your setup files in a Git repository, then set its URL and branch, tag, or other Git ref in `config.toml`:

```toml
[source]
repository = "https://github.com/your-account/dotfiles"
ref = "main"
```

Outfitting retrieves the files needed for the selected platform and profile, rather than copying the whole repository. To use files from a folder on this machine, see [Local setup files](/docs/source/local-sources/).

## Refresh setup files

Whether Outfitting refreshes files from the repository depends on the command:

- `init`, Linux/macOS `apply`, and Linux/macOS `nix` refresh the local copy by default. Use `--no-refresh` where available to reuse it.
- Linux `diff` uses the saved copy by default. Pass `--refresh` to fetch it again.
- Windows `apply`, macOS/Windows `diff`, `validate`, `status`, and `source path` do not refresh the repository copy.

```sh
# Refresh setup files from the Git repository
outfitting-manager init

# Reuse the existing copy
outfitting-manager init --no-refresh
```

`--no-refresh` controls only whether Outfitting refreshes its local copy of setup files; it does not prevent package managers or Nix from using the network.

## Access and requirements

For a private GitHub repository, sign in with the GitHub CLI and use an account that can read the repository. For GitHub Enterprise, use its hostname:

```sh
gh auth login --hostname github.com
gh auth login --hostname github.example.com
```

Other Git hosts use your configured Git credentials. Remote Git repositories do not support symlinks or submodules; use a [local folder or checkout](/docs/source/local-sources/) instead.
